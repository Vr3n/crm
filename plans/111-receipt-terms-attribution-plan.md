## 1. Context & ubiquitous language

Per `plans/CONTEXT.md` / `docs/pdf-generation.md` / `docs/05-payments-and-finance.md`:

- **Invoice** (DRAFT → Finalization → OPEN) + **Invoice Line** snapshot + **Billing Snapshot**; financial values immutable after Finalization.
- **Payment** = money received (never edited/deleted); **Payment Allocation** links Payment→Invoice; **Refund** layered on Payment (never deletes it); **Credit** held for future obligation. Refund != Credit != Reversal.
- **User** = login identity; **OrganizationStaff** = User-in-Organization binding with single **Role**; **Permission** codes gate Commands (`invoice.view`, `payment.view`, `refund.view`); super Role short-circuits.
- Original plan says "Repayment PDFs" — canonical term is **Refund receipt**.

Current state (verified read-only): `src/main/pdf/templates/` has **zero** T&C hits; `shared.ts:281-288` footer is only "Generated by CrownCRM · generatedAt · computer-generated document". `pdf.ts:268-290,344-367` resolves `receivedBy/recordedBy` via `created_by → users.full_name ?? 'System'`. Invoice doc has **no attribution line at all**. Write-path already stamps `requireSession().userId` (`finance.ts:183,345,449`, `billing.ts:83,246`) — the bug is display-only, not write-path.

## 2. Internet research (per AGENTS.md — research first)

- Common gym receipt/membership T&C patterns (Fitness First India membership terms; PureGym 2026 user terms; Gymbox 2026 terms; The Gym Group membership agreement; LegalZoom gym agreement template; Vyapar/myinvoicegenerator GST invoice guidance):
  1. Fees non-refundable / non-transferable; validity bound to Membership window (`start → end`).
  2. Valid receipt required for entry; follow club rules / timings.
  3. Injury / health waiver; medical clearance is the Customer's responsibility.
  4. Freeze / Proration / Cancellation per Plan policy only (per-Plan configurable data, not global).
  5. GST Invoice is final; historical lines never recomputed from current catalog.
  6. Refund layered on Payment; Credit applicable to future obligation; disputes subject to Organization city jurisdiction.
- PDF layering precedent in repo: `docs/pdf-generation.md` (renderer → `renderPdf(html, filename, subdir)` → Documents/CrownCRM/{Invoices,Receipts,Refunds}); org branding (`logo/address/gstin/mobileNumber/invoicePrefix`) flows via `getOrgBranding() → OrgBranding → buildOrgHeader()`. T&C follows the same pipe.

Decision (grilling answer applied): **per-type T&C columns, live-read on print** (not snapshot). If counsel later requires freeze-at-issue, add snapshot as follow-up ADR.

## 3. Scope

1. Three nullable Organization settings fields feeding three PDF footers.
2. Attribution fix + Invoice attribution addition (proposal — ratify in build):
   - Invoice → `Finalized By: <User.full_name> (<Role>)` from `invoices.finalized_by`.
   - Payment → `Received By: <User.full_name> (<Role>)` from `payments.created_by`.
   - Refund → `Recorded By: <User.full_name> (<Role>)` from `refunds.created_by`.
   - Fallback `Unknown User` only when User row missing; never hardcoded personal name.
3. `generatedAt` rendered in Organization timezone (today `formatNow()` uses device locale without explicit tz).
4. T&C editable in Organization settings; reflected on next print without touching historical Invoice Lines / Billing Snapshot / Outstanding Balance derivation.
