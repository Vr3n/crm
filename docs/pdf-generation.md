# PDF Generation — Invoice Documents & Payment Receipts

**Module:** PDF Export (cross-cutting, uses Module 04 + 05 data)
**Status:** Implemented
**Date:** 30 Aug 2026

## Overview

PDF generation produces printable Invoice Documents and Payment Receipts using
Electron's built-in `webContents.printToPDF()`. Zero external dependencies —
Chromium handles rendering.

## Architecture

```
Renderer (button click)
  → IPC: pdf:exportInvoice / pdf:exportReceipt
    → Main process: Application use-case
      → Hydrate Print Context (org + invoice/payment + relations)
      → Build HTML from Template + Data
      → PDF Renderer: hidden BrowserWindow
        → Load data: URL with HTML
        → Wait for document.fonts.ready
        → Call printToPDF(options)
        → Write Buffer to file
      → Return file path
    → Renderer: toast success with file path
```

## IPC Channels

| Channel | Input | Output | Permission |
|---------|-------|--------|------------|
| `pdf:exportInvoice` | `{ invoiceId: number, mode?: 'save' \| 'preview' }` | `string` (file path) | `invoice.view` |
| `pdf:exportReceipt` | `{ paymentId: number, mode?: 'save' \| 'preview' }` | `string` (file path) | `finance.view` |

## Export Modes

- **`preview`** (default): Generates PDF to temp directory, opens in system PDF
  viewer via `shell.openPath()`. User can print/save from there.
- **`save`**: Generates PDF to `Documents/GymCRM/Invoices/` or
  `Documents/GymCRM/Receipts/`. Creates directory if missing.

## Template Design

Print-only HTML with absolute CSS dimensions (no Tailwind). Key principles:

1. **A4 page size** with 12mm padding
2. **System fonts** (no bundled fonts — consistent with OS rendering)
3. **Inline styles** only — no external CSS dependencies
4. **Conditional logo** — if `org.logo` is null, renders text-only org name
5. **HTML escaping** — all user data escaped to prevent XSS
